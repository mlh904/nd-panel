# 茉莉音乐 · Navidrome 多服控制台

一个跑在浏览器里的 **Navidrome 多服务器管理面板**，单文件后端、零前端依赖、自带一套「茉莉书房」主题。
把分散在几台机器上的音乐库，收拢到一个页面上看、管、求歌、审歌。

> 纯 Python 标准库 + 原生 JS，不引入任何前端框架。前后端合计约 2400 行。

---

## 它解决什么问题

自建 Navidrome 的人通常会遇到三件事：

1. **库分散** —— 一台机器装不下，就开第二台、第三台。结果用户在两个站点各注册一遍，同一个人的账号要重复建、重复删。
2. **没有运营工具** —— Navidrome 自带后台只有「扫描库」「管理用户」，没有求歌、审核、播放统计。
3. **看不出状态** —— 哪台挂了、哪台磁盘要满、今天谁在听什么，全靠一个个登录去看。

这个面板就是把这三件事收进一个界面。

## 功能

### 概览
三台线路的在线状态、曲库总量、累计播放、近 7 天播放，配一张 30 天播放趋势图。
顶部一行健康徽标，异常会变红。可一键跑完整自检。

### 正在播放 / 播放器排行
实时拉取各线路的 `/rest/getNowPlaying` 与客户端维度统计。
按 player client 聚合出设备数、在播数、使用用户数。

### 播放数据
热门歌曲、活跃听众、最近播放。数据来自每台机器上跑的**只读统计代理**（见下），
面板不直接碰数据库文件。

### 用户管理
- 三台同名账号合并展示，一次操作同步到所有线路，**失败自动回滚**
- 支持改密码、改显示名、提权、删号（删号有二次确认）
- 标记未绑定 Telegram 的账号，方便催用户自绑

### 求歌与审核
用户提交 → 管理员审核 → 标记已上传 / 拒绝。

- 四平台搜索：网易云、QQ 音乐、酷狗、酷我，**结果带专辑封面**
- 支持粘贴歌单链接批量解析
- 封面统一转 https、缩到 200px；取不到的显示音符占位，不留破图
- **重复检测**：同一首歌再被求时，直接告诉提交人「谁在什么时候求过、现在什么状态」
- 搜索历史联想，常用关键词变快捷入口
- 审核快捷键：`J/K` 上下、`A` 通过、`U` 标已上传、`R` 拒绝
- 按月配额：求歌 50 首 / 月、歌单 10 个 / 月，被拒绝的不占额度
- 审核结果通过绑定的 Telegram 推送给用户

### 健康自检
九项检查，覆盖线路 ping、统计代理、面板库、Bot 绑定库、磁盘余量。
出问题时给出具体原因，不是笼统的「失败」。

### 操作日志
所有写操作留痕，可按类型筛。

## 架构

```text
┌──────────────┐
│   浏览器      │
└──────┬───────┘
       │ HTTP
┌──────▼─────────────────────┐
│  nd-panel (Python 标准库)   │
│  ├─ 会话 / 权限            │
│  ├─ SQLite: 求歌·歌单·日志  │
│  └─ 并发聚合               │
└──┬────────┬────────┬───────┘
   │        │        │
┌──▼──┐  ┌──▼──┐  ┌──▼──┐
│线路1│  │线路2│  │线路3│  Navidrome Subsonic API
└──┬──┘  └──┬──┘  └──┬──┘
   │        │        │
┌──▼──┐  ┌──▼──┐  ┌──▼──┐
│代理1│  │代理2│  │代理3│  stats_agent.py（只读）
└─────┘  └─────┘  └─────┘
```

**为什么要有统计代理？**
Navidrome 的 HTTP API 不暴露 `playCount`、`playlist` 这类统计信息。
面板又不想直接挂载别人的数据库文件（跨机器挂载也麻烦），所以每台跑一个 60 行的小代理，
只执行写死的聚合 SQL、只读打开、令牌鉴权，面板通过 HTTP 拉结果。

## 快速开始

```bash
git clone https://github.com/mlh904/nd-panel.git
cd nd-panel

cp .env.example .env
# 编辑 .env，填你的 Navidrome 地址

mkdir -p secrets data
echo '你的Navidrome管理员密码' > secrets/nd_botadmin_pass
openssl rand -hex 32 > secrets/panel_secret
chmod 600 secrets/*

docker compose up -d
```

打开 `http://你的IP:3010`，用 Navidrome 账号登录。**管理员才能看到管理功能**。

### 部署统计代理（要用播放数据页才需要）

把 `stats_agent.py` 拷到每台音乐服务器：

```bash
mkdir -p /opt/nd-stats /etc/nd-stats
cp stats_agent.py /opt/nd-stats/
chmod 644 /opt/nd-stats/stats_agent.py

cat > /etc/nd-stats/env <<'EOF'
STATS_TOKEN=换成一串长随机
ND_DB=/path/to/navidrome.db
PORT=3999
BIND=0.0.0.0
EOF
chmod 600 /etc/nd-stats/env
```

systemd 单元示例见 [`STATS_AGENT.md`](STATS_AGENT.md)。

然后把地址填进 `.env` 的 `ND_STATS_SERVERS`，重启面板。

> **注意**：跨机访问记得同时放行云厂商安全组和本机防火墙。容器访问宿主请用 docker 网关 IP（通常 `172.x.x.1`），`127.0.0.1` 指向容器自己。

## 配置项

| 变量 | 默认 | 说明 |
|---|---|---|
| `PANEL_PORT` | 3010 | 对外端口 |
| `ND_ADMIN_USER` | botadmin | 管理员用户名 |
| `ND_SERVERS` | `[]` | Navidrome 线路，JSON 数组 |
| `ND_STATS_SERVERS` | `[]` | 统计代理地址，JSON 数组 |
| `STATS_TTL` | 60 | 统计缓存秒数 |

密钥文件说明见 [`secrets/README.md`](secrets/README.md)。

## 权限模型

| 能力 | 普通用户 | 管理员 |
|---|:--:|:--:|
| 概览 / 播放数据 | ✓ 脱敏 | ✓ 完整 |
| 求歌 / 歌单 / 查配额 | ✓ | ✓ |
| 用户管理 | ✗ | ✓ |
| 审核 | ✗ | ✓ |
| 线路详情 / 日志 / 自检 / 数据对照 | ✗ | ✓ |

普通用户看到的播放数据是**脱敏版**：不显示线路名称、听众昵称、最近播放所属服务器。
后端对每个管理员接口单独校验，前端隐藏只是体验，不是安全边界。

## 设计

主题叫「茉莉书房」——雾霾蓝紫纸底、衬线标题、赭红书签、雾金点缀，洛可可式描金角饰。
登录页是一朵重瓣茉莉，登录成功有翻书过场。

纸感不是平涂出来的：三层极淡叠加——边缘微晕 + 0.55px 细噪点 + 几乎看不见的纤维斜纹。
小屏会去掉斜纹，否则噪点密度过高会显成条纹布。

没有用一个 emoji，所有图形都是内联 SVG 或 CSS 绘制。

设计取舍、配色变量、动效参数详见 [`DESIGN.md`](DESIGN.md)。

## 已知限制

- **没有内置多租户隔离**：面板假定你信任自己的用户群，普通用户只做功能裁剪。
- **统计维度受 Navidrome 限制**：`scrobbles` 表没有 player_id，做不出「每个播放器播了多少次」，只能到设备维度。
- **音乐平台接口非官方**：搜索依赖各平台公开的 web 接口，随时可能失效或改字段。失效时搜索页会报错，不影响其他功能。
- **封面不是每首都取得到**：酷狗搜索接口本身不返回封面，要靠 `album_id` 二次查询，部分冷门专辑查不到；四个平台平均覆盖率约 75%，取不到时显示音符占位。
- **不支持 SQLite 以外的存储**：求歌记录存在本地 SQLite，没做迁移工具。
- **轮询式刷新**：正在播放靠定时拉取，不是 WebSocket 推送。
